## Trace

2. [WCAG 2.2 SC 3.2.2 On Input](https://www.w3.org/TR/WCAG22/#on-input) (Level A): changing the **setting** of any UI component must not automatically cause a [change of context](https://www.w3.org/WAI/WCAG22/Understanding/on-input.html) unless the user is advised first. Understanding: checking a checkbox, entering text, or changing a select **changes a setting**; activating a link or a submit/navigation button does **not**. A change of content is not always a change of context; the SC is met if content changes are not also context changes. Failures [F36](https://www.w3.org/WAI/WCAG22/Techniques/failures/F36) / [F37](https://www.w3.org/WAI/WCAG22/Techniques/failures/F37): auto-submit or new window on radio/checkbox/select change.
3. Host interactive controls:
   - Theme toggle: `<button type="button">` with `{{on "click" this.toggleTheme}}` only. No `aria-pressed`. No `change`/`input` listener. Click activation restyles `data-theme` / `.dark`; no navigation, new window, focus move, or meaning change of the page.
   - Cookie Preferences: `<button type="button">` with `{{on "click" this.openCookiePreferences}}` → `CookieConsent.showPreferences()`. Modal open is activation, not a setting change.
   - FAQ: native `<details>`/`<summary>`; panel toggles on activation.
   - Hero, action-pill, footer, Contact CTA: `<a>` activation (some `target="_blank"`).
4. Host markup has **no** `<input>`, `<select>`, `<textarea>`, checkbox, or radio. Repo-wide search in `app/` found no `onchange` / `oninput` / `addEventListener("change")` besides `CookieConsent.run({ onChange: syncGtm })`.
5. `onChange: syncGtm` updates Consent Mode and may inject GTM after consent is recorded (Accept all / Save preferences). That is script/analytics side effect, not a change of context (no user agent, viewport, focus, or page-meaning change).

Authz/validation/persistence: public demo; theme persist (`qc-theme`); geo consent cache. No form-setting-triggered navigation.

## Falsification

- **Theme toggle is a stateful button, so 3.2.2 applies and theme swap is a change of context:** Understanding treats toggle buttons with `aria-pressed` as setting changes, but still requires a **change of context**. Restyling the same document is a change of content/appearance, not context. The control has no `aria-pressed` and is activated by click, not `change`.
- **`target="_blank"` on links fails 3.2.2:** F37 is launching a window when a **radio/checkbox/select setting** changes. Links open on activation.
- **Cookie Preferences / first-layer modal steals focus:** opening a dialog is button activation (Understanding: buttons that move focus are activating, not changing a setting). First layer uses `autoShow: required` on load, not on a form setting change.
- **`onChange: syncGtm` auto-loads GTM when a category toggle flips:** even if the library fires on category change, injecting GTM is not a change of context. Host has no submit-on-change form.
- **Issue search** `3.2.2 OR on-input OR "on input"` and `"change of context"`: no matching issue. No issue created (report-only).
